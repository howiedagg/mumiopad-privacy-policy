繁體中文

本政策適用於 Mumio Android 行動應用程式（原名 Mumiopad），說明手機端資料處理及與所選裝置之間的滑鼠、鍵盤控制。Wi-Fi 模式使用電腦上的 Mumio Server；電腦端的詳細儲存、更新與刪除方式見 Mumio Server Windows 隱私權政策。

1. 資料處理原則

Mumio 不要求建立使用者帳號，程式不內建廣告、分析或遙測服務，也不出售控制內容。滑鼠與鍵盤指令送到您選擇的裝置，不會自動上傳給開發者。輸入文字、語音、裝置名稱及網路識別資訊可能包含個人或敏感資訊；系統語音辨識、主機名稱解析、政策網頁與您主動提出的支援請求可能涉及其他服務，詳見下文。

2. 存取與處理的資料及用途

  • 連線與探索：App 接收區域網路 mDNS 探索資訊，包括電腦名稱、IP、伺服器識別碼、服務埠及協定版本，以尋找可連線電腦。Wi-Fi 控制透過您選擇的網路地址建立連線，通常使用區域網路，也可能經您配置的 VPN 或其他可達網路；藍牙模式透過系統已配對裝置提供 HID 滑鼠與鍵盤控制。
  • 手機名稱：App 在 Wi-Fi 配對及重新認證時，將系統設定的手機裝置名稱傳給所選電腦；無法取得可用名稱時，才使用廠牌與型號等預設名稱。名稱用於辨識與管理已授權手機；自訂名稱可能包含姓名。
  • 配對、地址與設定：App 在手機保存電腦名稱、UUID、配對 token、TLS 公鑰 pin、設定的 IP／主機名稱與埠、成功連線地址及其對應來源、常用／所選電腦、藍牙裝置位址與類型，以及操作偏好、手勢與布局設定。這些資料用於重新連線、裝置管理及保留設定。
  • Wi-Fi 網路識別：取得適用權限後，App 讀取並在本機保存目前 Wi-Fi 路由器的 BSSID 與預設電腦對應，用於依網路切換連線目標。BSSID 不會送給開發者，也不用於查詢或追蹤 GPS／實際地理座標。
  • 控制與文字輸入：App 處理觸控、手勢、按鍵及您主動輸入的文字，轉成控制指令送給所選裝置。程式不建立輸入文字或控制操作的歷史紀錄。文字可能包含姓名、電話或其他個人資訊。
  • 相機與 QR：您選擇掃描連線 QR 時，App 使用相機在手機上辨識 QR，解析主機地址、埠、伺服器 UUID 及 TLS 公鑰 pin，再驗證目標電腦並進行地址設定或配對。Mumio 不保存或上傳相機照片或影片。
  • 語音輸入：您啟動語音輸入並允許麥克風後，App 呼叫手機的系統語音辨識服務。辨識文字暫留在輸入畫面，可編輯，按「送出」後才交給所選裝置。Mumio 不建立錄音檔或語音歷史；系統服務可能將音訊送到其供應者的伺服器，詳見第 7 節。關閉語音畫面或 App 進入背景時，程式會結束目前的辨識工作階段。
  • 陀螺儀：啟用相關控制功能或試用時，App 在手機上處理陀螺儀的角速度與時間資料，轉成游標等控制操作；不建立感測器歷史，也不將原始陀螺儀樣本自動上傳給開發者。
  • 診斷資訊：程式可能在 Android 診斷日誌寫入連線狀態、裝置識別碼、網路地址、藍牙位址及錯誤細節，協助排除問題；不內建自動向開發者上傳這些日誌的服務。

3. Android 權限與選擇

  • 相機（CAMERA）：用於您主動選擇的 QR 掃描。您可拒絕此權限並手動輸入地址。
  • 麥克風（RECORD_AUDIO）：用於語音辨識。您可拒絕此權限並直接輸入文字。
  • 位置（ACCESS_FINE_LOCATION / ACCESS_COARSE_LOCATION）：用於取得 Android 視為位置相關資訊的 BSSID。App 不呼叫 GPS 定位；無法取得 BSSID 時，依 Wi-Fi 網路記住預設電腦的功能會受限。
  • 藍牙（BLUETOOTH_CONNECT，舊版 Android 使用相應藍牙權限）：用於查看與連線系統已配對的裝置、HID 控制及您要求的配對管理。拒絕後，藍牙控制功能無法使用。
  • 網路與鄰近 Wi-Fi（INTERNET / NEARBY_WIFI_DEVICES）：用於網路連線及探索。程式另使用系統網路狀態、Wi-Fi 狀態、群播及 Wi-Fi 鎖等能力，判斷連線並維持控制反應。您可在 Android 系統設定管理可撤銷的權限。

4. 手機儲存與安全

Wi-Fi 配對資料，包括 token 與 TLS 公鑰 pin，使用 EncryptedSharedPreferences 加密保存在手機。BSSID 對應、藍牙位址及一般設定保存在 App 私有儲存空間。App 在 Android Manifest 中停用一般 Android 備份，不提供 Mumio 帳號或自有雲端備份服務。

Wi-Fi 控制使用 WSS/TLS、電腦公鑰驗證、使用者確認的配對及 token 認證；藍牙控制使用 Android 系統的藍牙配對與連線機制。您可以停止控制、斷線或撤銷配對，管理裝置存取。

5. 跨端處理與揭露

所選電腦會處理連線來源 IP，並保存手機名稱、配對識別、token 雜湊及最後連線時間，用於驗證及管理裝置。控制指令與文字交給您正在控制的目標應用程式。Mumio Server 收到的是您送出的指令與文字，不會從這些功能收到手機的相機影像或原始錄音。

Wi-Fi 文字貼上時，Mumio Server 會讀取當時可讀取的 Windows 剪貼簿文字、暫放手機文字並執行貼上，再嘗試還原先前文字；沒有可還原文字時則清除暫放內容。原剪貼簿文字不會傳回手機或自動傳給開發者。Windows 剪貼簿歷程／同步（若啟用）及目標應用程式仍可能另行保存或傳輸文字，取決於其設定與政策。電腦端詳細方式見 Windows 政策。

6. 資料保留與刪除

  • 手機資料：配對、地址、網路對應與設定保留至您移除相應紀錄、清除 App 資料或解除安裝。移除電腦配對時，也會移除指向該電腦的 BSSID 對應；您亦可在連線設定管理網路對應與地址。
  • Wi-Fi 解除配對：連線時，App 會要求電腦撤銷配對授權，收到成功回覆後刪除手機紀錄。離線時經您確認移除，只會刪除手機紀錄，電腦上的授權仍需在 Mumio Server 移除。清除 App 資料或解除安裝也不會替您遠端刪除電腦紀錄。
  • 藍牙配對：App 解除配對時會移除自己的裝置紀錄，並嘗試透過 Android 系統解除藍牙配對。單純清除 App 資料或解除安裝不保證刪除系統配對；可在 Android 藍牙設定另行管理。
  • 文字、音訊與影像：Mumio 不建立這些內容的歷史。辨識服務、Windows 剪貼簿及目標應用程式持有的資料由其服務與設定管理；移除 Mumio 配對或 App 不會刪除這些獨立副本。

7. 系統與第三方服務

  • 系統語音辨識：實際供應者及離線／線上處理方式取決於手機安裝的辨識服務與設定。此 App 沒有強制使用離線辨識；音訊及相關請求資訊的傳輸、保存、安全及刪除依該供應者政策。您可查看手機的語音輸入／辨識服務設定，或不用語音功能。
  • 主機名稱解析：輸入或掃描的連線地址若為主機名稱，App 使用 Android 系統解析器查詢其 IP；DNS 服務可能處理查詢的名稱與連線資訊。此查詢不包含您的控制文字、配對 token 或錄音。
  • Google Play：透過 Google Play 安裝的版本由 Google Play 提供配送與更新，App 沒有自有更新檢查器。Google 依其服務設定及 Google 隱私權政策處理商店服務相關資料；此說明不代表手機語音辨識一定由 Google 提供。
  • 政策與支援：本頁由 GitHub Pages 提供，聯絡入口使用 GitHub Issues。GitHub 依 GitHub 隱私權聲明處理連線與您主動提供的資料。

8. 聯絡開發者與政策更新

開發者：Mumio（GitHub：howiedagg）。政策問題或適用法律下的資料存取、更正、刪除等請求，可透過 Mumio 隱私權政策 GitHub Issues提出。開發者無法遠端讀取或刪除您裝置上的本機資料，您可依第 6 節自行管理。

此入口為公開討論，內容可能公開顯示。請只提供處理請求所需的資訊，不要張貼輸入文字、錄音、剪貼簿內容或配對憑證。開發者只將您主動提供的支援資料用於回覆與處理請求，自行持有的副本保留至請求處理完成且不再需要後續追蹤，之後刪除；您也可提出刪除請求。GitHub 議題的保留及刪除另受平台功能與政策影響。

English

This policy applies to the Mumio Android app (formerly Mumiopad), covering data processing on the phone and mouse and keyboard control of your chosen devices. Wi-Fi mode uses Mumio Server on the PC. For detailed PC storage, updates, and deletion, see the Mumio Server Windows privacy policy.

1. Data Processing Principles

Mumio does not require a user account, has no built-in advertising, analytics, or telemetry services, and does not sell control content. Mouse and keyboard commands are sent to your chosen device, not automatically uploaded to the developer. Input text, speech, device names, and network identifiers may contain personal or sensitive information. System speech recognition, hostname resolution, this policy page, and support requests you initiate may involve other services, as explained below.

2. Data Accessed and Processed, and Its Purpose

  • Connections and discovery: The app receives local mDNS discovery information, including PC names, IP addresses, server identifiers, service ports, and protocol versions, to find available PCs. Wi-Fi control connects to the network address you choose, usually on a local network, but potentially through a VPN or another reachable network you configure. Bluetooth mode uses system-paired devices for HID mouse and keyboard control.
  • Phone name: During Wi-Fi pairing and reauthentication, the app sends the phone's system-configured device name to your chosen PC. If no usable name is available, it falls back to a default such as the manufacturer and model. This helps identify and manage authorized phones; a custom name may contain a person's name.
  • Pairings, addresses, and preferences: The app stores PC names, UUIDs, pairing tokens, TLS public-key pins, configured IP addresses or hostnames and ports, successful connection addresses and their source associations, common or selected PCs, Bluetooth device addresses and types, and control, gesture, and layout preferences on the phone. These data support reconnection, device management, and retained preferences.
  • Wi-Fi network identification: With the applicable permissions, the app reads and stores the current router's BSSID and preferred-PC association locally to choose a connection target by network. The BSSID is not sent to the developer or used to look up or track GPS or physical location coordinates.
  • Control and text input: The app processes touch, gestures, keys, and text you intentionally enter, converting them into commands for your chosen device. It does not create a history of input text or control operations. Text may contain names, telephone numbers, or other personal information.
  • Camera and QR codes: When you choose to scan a connection QR code, the app uses the camera to decode it on the phone, obtaining the host address, port, server UUID, and TLS public-key pin. It then verifies the target PC for address configuration or pairing. Mumio does not save or upload camera photos or video.
  • Voice input: When you start voice input and allow microphone access, the app calls the phone's system speech-recognition service. Recognized text remains temporarily in the input screen for editing and is sent to the chosen device only when you select Send. Mumio does not create audio recordings or a speech history; the system service may send audio to its provider's servers, as described in Section 7. Closing the voice screen or moving the app to the background ends the current recognition session.
  • Gyroscope: When you enable or try the relevant controls, the app processes gyroscope angular-velocity and timing data on the phone to produce cursor and other control operations. It does not create a sensor history or automatically upload raw gyroscope samples to the developer.
  • Diagnostics: The app may write connection status, device identifiers, network addresses, Bluetooth addresses, and error details to Android diagnostic logs for troubleshooting. It has no built-in service that automatically uploads these logs to the developer.

3. Android Permissions and Choices

  • Camera (CAMERA): Used for QR scanning you initiate. You can deny it and enter an address manually.
  • Microphone (RECORD_AUDIO): Used for speech recognition. You can deny it and enter text manually.
  • Location (ACCESS_FINE_LOCATION / ACCESS_COARSE_LOCATION): Used to obtain the BSSID, which Android treats as location-related information. The app does not request GPS positioning. Without a usable BSSID, remembering the preferred PC by Wi-Fi network is limited.
  • Bluetooth (BLUETOOTH_CONNECT, or the corresponding permissions on older Android versions): Used to view and connect to system-paired devices, provide HID control, and manage pairings at your request. Bluetooth control is unavailable if permission is denied.
  • Network and nearby Wi-Fi (INTERNET / NEARBY_WIFI_DEVICES): Used for network connections and discovery. The app also uses system network-state, Wi-Fi-state, multicast, and Wi-Fi-lock capabilities to monitor connectivity and maintain responsive control. You can manage revocable permissions in Android settings.

4. Phone Storage and Security

Wi-Fi pairing data, including tokens and TLS public-key pins, are encrypted on the phone with EncryptedSharedPreferences. BSSID associations, Bluetooth addresses, and general preferences are kept in the app's private storage. The Android manifest disables ordinary Android backup; the app provides no Mumio account or developer-operated cloud backup.

Wi-Fi control uses WSS/TLS, PC public-key verification, user-confirmed pairing, and token authentication. Bluetooth control uses Android's system pairing and connection mechanisms. You can stop control, disconnect, or revoke pairings to manage device access.

5. Cross-Device Processing and Disclosure

Your chosen PC processes the connection's source IP address and retains the phone name, pairing identifier, token hash, and last-connection time for authentication and device management. Control commands and text are delivered to the destination application you are controlling. Through these features, Mumio Server receives your submitted commands and text, not the phone's camera images or original audio.

For Wi-Fi text pasting, Mumio Server reads accessible Windows clipboard text, temporarily inserts the phone's text, pastes it, and attempts to restore the previous text, or clears the temporary content if no text can be restored. Existing clipboard text is not returned to the phone or automatically sent to the developer. Windows clipboard history or synchronization (if enabled) and destination applications may independently retain or transmit text according to their settings and policies. See the Windows policy for PC details.

6. Retention and Deletion

  • Phone data: Pairings, addresses, network associations, and preferences remain until you remove the relevant records, clear app data, or uninstall the app. Removing a PC pairing also removes BSSID associations pointing to that PC. You can also manage network associations and addresses in connection settings.
  • Wi-Fi unpairing: When connected, the app requests that the PC revoke pairing authorization and deletes the phone's record after a successful reply. Offline removal, after your confirmation, deletes only the phone's record; authorization on the PC must be removed in Mumio Server separately. Clearing app data or uninstalling also does not remotely delete PC records.
  • Bluetooth pairings: Unpairing in the app removes its device record and attempts to remove the Android system pairing. Clearing app data or uninstalling does not guarantee removal of system pairings; you can manage them separately in Android Bluetooth settings.
  • Text, audio, and images: Mumio does not create histories of these content types. Data held by recognition services, the Windows clipboard, and destination applications are governed by those services and settings. Removing a Mumio pairing or uninstalling the app does not delete these independent copies.

7. System and Third-Party Services

  • System speech recognition: The provider and offline or online processing depend on the recognition service installed on the phone and its settings. This app does not enforce offline recognition. Transmission, retention, security, and deletion of audio and related request information depend on that provider's policy. You can check the phone's voice-input or recognition-service settings, or choose not to use voice input.
  • Hostname resolution: If an entered or scanned address is a hostname, the app uses Android's system resolver to look up its IP address. DNS services may process the queried name and connection information. The query does not contain your control text, pairing token, or audio.
  • Google Play: Editions installed through Google Play are distributed and updated by Google Play. The app has no developer-operated update checker. Google processes store-service data according to its settings and Google Privacy Policy. This does not mean that the phone's speech-recognition provider is necessarily Google.
  • Policy and support: This page is hosted on GitHub Pages, and the contact channel uses GitHub Issues. GitHub processes connections and information you actively provide under the GitHub Privacy Statement.

8. Developer Contact and Policy Changes

Developer: Mumio (GitHub: howiedagg). For policy questions or requests for access, correction, deletion, or other rights under applicable law, use Mumio privacy-policy GitHub Issues. The developer cannot remotely read or delete local data on your devices; you can manage it as described in Section 6.

This is a public discussion channel, and submitted content may be publicly visible. Provide only information needed to handle your request, and do not post input text, audio, clipboard content, or pairing credentials. The developer uses information you actively provide only to respond to and handle your request. Independently held copies are retained until the request is resolved and follow-up is no longer needed, then deleted; you can also request deletion. Retention and deletion of GitHub issues separately depend on the platform's features and policies.

This policy will be updated when actual data-processing practices change, with the last-updated date shown on this page.
